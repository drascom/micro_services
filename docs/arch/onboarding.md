## Resolver, oynatıcı yazdırma, provider kütüphanesi, oynatılabilirlik

- **Resolver (Faz 0)** `scraper/resolvers/`: yaml `resolvers:` düz öğe listesi `{type..parametre}`; tipler `iframe|anchor_host|data_attr_token|ajax_handoff|json_api` (`TYPES`, `validate()`, `catalog()`, `params_of()`, `make_ctx()`); ağ yalnızca `ctx.fetch` (`fetch_url/post_url`), her aşama `trace.note`. `site_extractors.discover/resolve_candidate(site_id.., cfg=None)`: liste varsa site modülü ÇAĞRILMAZ (`use_site_module: true` modül adaylarını ekler), adaylar `resolver` (liste indeksi) + `resolver_type` taşır, liste yoksa eski modül yolu aynen. cfg yaml yoluyla (mtime) önbelleklenir. `ajax_handoff`/`data_attr_token` hand-off: `cookie_seed` hafif çerezle dener, `browser_fallback` ile `load_cookies`'a geçer. `json_api` = `stream_resolver` alanları (`type` yerine `media_type`), sonuç `candidate["stream"]` ve provider adımı atlanır. `providers/registry.py`: `PROVIDERS` (vidmolly, okru), `resolve(.., allowed=)` (`providers:` yaml'dan; `[]`/geçersiz = hepsi), `catalog()`. `SiteConfig.resolvers/.providers/.use_site_module` (bozuk öğe loglanıp atlanır). `videos.RESOLVER_VERSION=6`, `last_resolver.candidates[].resolver_type`. `GET /api/ops/resolvers` -> `{resolvers, providers}`. Yabancidizi eşdeğerlik testi genelleşmeyenleri belgeler: `data-lango` aktif sekme dili, `_safe_token` dönüşümü, curl_cffi TLS taklidi, aynı oturum çerezi, boş `data-querytype` varsayılanı
- **`embedded_json` (7. resolver tipi)** sayfanın KENDİSİNE gömülü JSON'dan kaynak çıkarır (ek istek/`follow` yok; `discover` zaten detay/bölüm HTML'ini alır): `<script type="application/json">`/`__NEXT_DATA__` (ilk anahtar her derinlikte aranır) ya da Next.js flight parçaları (`self.__next_f.push([1,".."])` birleştirilip JSON-kaçışı çözülür, ilk `json_path` anahtarı `"key":` ile bulunur, `raw_decode` ile dengeli blok okunur: iki push'a bölünmüş JSON sorun değil). Parametreler: `json_path` (zorunlu, `chapterContent.sources[*]` nesneler ya da `..sources[*].url` düz URL), `source auto|json_script|flight`, `url_field` (url), `label_field` (name), `label`, `host_regex`, `lang`. `//ok.ru/.` -> `https:`; adaylar `resolver_type: embedded_json` taşır, host'a göre provider kütüphanesine gider (bilinmeyen host'u kayıt defteri eskisi gibi atlar), `label` = kaynak adı. Üst sınırlar 3 MB HTML / 24 aday. Ajan `references/resolvers.md` katalogundan görür (`gen_onboard_refs`)
- **Oynatıcı yazdırma (`player_page` + `grep_page`)**: bilinen provider'ı olmayan ya da sitenin KENDİ host'unda (örn. `/player/oynat/<hash>`) olan oynatıcılar için LLM kod yazmaz, yaml'a deklaratif tarif yazar. `resolvers/player_page.py` = 6. tip: `selector` ile oynatıcı URL'sini bulur, `fetch: http|browser` (browser = `fetch.browser_page`, Cloudflare/JS oynatıcılar; sitenin `fetch_mode`'undan bağımsız), `follow` (≤2, iç içe iframe), `extract` (≤8 kural: `regex|css+attr|json_path`, `unpack` p.a.c.k.e.r. (`resolvers/_unpack.py`, kod çalıştırmaz), `base64`, `unescape`, `type auto|hls|mp4`), `verify`. Akış bulunursa `{.., "stream": {..}}` (json_api gibi provider adımı atlanır), bulunmazsa son sayfadaki ilk `iframe[src]` ile registry'ye devam. Http modu `fetch.fetch_limited` (her yönlendirme `netguard`), browser modunda yalnız ilk URL denetlenir (transport yönlendirme bildirmiyor: bilinen açık). `fetch: http` = `fetch.fetch_impersonated/impersonated_get/impersonated_session` (curl_cffi Chrome TLS parmak izi + Referer/header/çerez; Cloudflare TLS denetimini geçer, sandbox crawlee/Obscura'nın veremediği Referer'ı verir; her hop `allow`/netguard, 3 MB, süre sınırı, retry yok); `warm_session: true` önce detay sayfasını aynı oturumda GET eder. Sandbox `POST /fetch` `referer` ya da `mode: chrome` ile aynı taşımayı kullanır (`fetch_mode: chrome` yaml `fetch_mode` DEĞİLDİR). Gerçek vaka (trdiziizle): oynatıcı sayfası Referer'sız 404, düz httpx/curl'de Cloudflare 403, Chrome-TLS+Referer ile 200 ve `sources:[{file:"https://downloader.disk.yandex.ru/..mp4"}]` (doğrudan mp4, 302 -> storage host, Range var, Referer GÖNDERİLİRSE Yandex 403: istemci Referer göndermemeli, `moov` sonda). Regex'ler katastrofik geri izleme sezgisiyle ve ≤500 karakterle sınırlı. Canlı süre: `fetch: browser` adayına `timeout` damgalanır (`RESOLVE_BROWSER_TIMEOUT`, varsayılan 40 sn); `videos.live_limits` aday süresini `max(RESOLVE_CANDIDATE_TIMEOUT, timeout)`, toplamı `max(RESOLVE_TOTAL_TIMEOUT, en uzun+2)` yapar (timeout'suz adaylar ve `RESOLVE_GRACE` aynen; sandbox uyarısı da buna göre). Sandbox: `POST /api/onboard/sandbox/grep` + pi aracı `grep_page` (regex ayrı alt süreçte 5 sn tavan); `test_resolvers` cevabı `status` (`resolved|no_stream|no_candidates|error`), `resolved_ok`, aday başına `host/stream_type/ms/trace`. Skill'de "Player authoring" bölümü + `references/player-authoring.md` (çalışan tarif örnekleri, testte gerçekten koşturulur). Strateji: video sağlayıcıları az (5-10); `player_page` köprü, üçüncü taraf host'lar birkaç sitede doğrulanınca adlandırılmış provider'a terfi ettirilir, sonra ajan yalnız katalogdan seçer
- **`blocked_hosts:`** (site yaml üst düzeyi, isteğe bağlı) `[abyssplayer.com, ...]`: bu host ya da alt alan adlarındaki oynatıcı adayları çözümlemeden ÖNCE elenir (`videos.drop_blocked`, `badhosts.blocked_host`), ne denenir ne listelenir. Gerekçe: `providers:` yalnız TANINAN host'ları süzer; tanınmayan host (ör. Abyss, 4Me) genel iframe hand-off yoluna düşüp denenir. `RESOLVER_VERSION=9` ile eski önbellek yükleri yeniden çözülür.
- **Provider kütüphanesi (veri-tabanlı tarifler)** İLKE: site tasarımı site yaml'ında, video host bilgisi kütüphanede; ajan önce katalogdan seçer, yeni host varsa KÜTÜPHANE için tarif yazar (site yaml'ına `player_page` gömmez). `scraper/providers/recipes.py` + `scraper/configs/providers/<ad>.yaml` (sürüm arşivi `<ad>.vN.yaml`; sunucu referans, yerel ayna; `deploy.sh` site yaml'ıyla aynı karar mantığı, REMOTEONLY `yerele çekildi: provider <ad> (vN)`). Tarif: `name, description, version, match{host_regex, path_regex?}, fetch http|browser, referer, headers, warm_session, follow, extract, stream_headers, verify, cache_ttl?` (`resolve_player()` çekirdeği `resolvers/player_page.py`'de ortak). `registry.PROVIDERS` canlı görünüm (önce kod, sonra tarifler), `catalog()` girdisi `kind: code|recipe`, `resolve(.., extra=[..])`. Site yaml'ı yalnız `resolvers:` (oynatıcı URL'sini bul) + `providers: [<ad>]`. Sandbox `POST /test_provider`, `provider_recipes` (test_config/test_resolvers/submit_repair; öneri tarifleri diske yazılmaz, heal kapıları geçerse heal yazar).
- **Oynatılabilirlik doğrulaması + dayanıklılık:** `normalize.preview` `with_video_sources/episode_items/series_without_sources`; `test_config(playable)` en çok 3 FARKLI örneği uçtan uca çözer (normalize -> oynatma sayfası -> resolvers -> akış; DB'ye yazmaz); kriterler `playable_ratio` (≥0.67), `series_have_episode_sources` (≥0.9; `video_sources` YA DA `series_page` envanteri), `series_inventory_ok`. `episode_source.default_season`; yinelenen-anahtar sayımı yalnız aynı başlık+aynı bölüm. `test_resolvers` çok sayfalı (`detail_urls`, `list_page_id`, `pages[]`, durum `resolved|partial|no_stream|no_candidates|error`, "varied hosts/types" uyarısı). `player_page`: `type` varsayılan `auto`, URL uzantısı (`.m3u8`->hls, `.mp4`->mp4) deklare tipi ezer, `quality_group/label_group` ile çok kaliteli `sources` sıralı akışlar
- **`match_providers`** `scraper/provider_match.py` (`POST /match_providers`): tüm kütüphane sağlayıcıları host eşleşmesi yok sayılarak tek paylaşımlı istekle kuru koşar -> `recommendation` `use_provider|add_host|new_recipe|needs_code`. `provider_recipes[].mode: "update"` = var olan tarifin yeni sürümü, yalnız `match.host_regex` genişler (`recipes.update_problems`).

- **pi skill + extension** `server/pi/` (deploy ile gider; dizin/dosya adları eski: `skills/diziflix-site-onboarding/`, `extensions/diziflix-onboard.ts`): SKILL.md yalnız REPAIR MODE, ayrıntı `references/heal.md` (+ format referansları). ## Admin "Siteler" (site yönetimi)

- `static/admin/sites.js` (hash `#onboard`, sekme adı "Siteler"): kayıtlı site listesi (YAML / Devir notu / Ad değiştir / Geri al / Şimdi tara / Arşivden parti / Sil) + site başına otomatik tarama kontrolleri + Canlı TV satırı. Yeni admin js dosyası `ops.py` `_ASSETS`'e eklenmeli.
- `routers/ops_sites.py`: `GET /api/ops/sites/manage` (kayıtlı TÜM siteler: sürüm, `auto_scan{enabled,interval_hours,next_scan_at,source,running,last_run_at}`, son koşu, sayımlar, `busy` scan|heal|archive|finder, `can_rollback`, `heal_cooldown_until`; üstte `any_enabled`/`limits`/`tick_seconds`, `live_sources`), `GET../{site}/config` (yaml, sırlar maskeli), `POST../{site}/rename` (yeni sürüm), `DELETE../{site}?purge=1|0`: silme `library/purge.py` tek transaction (başka sitede de kaynağı olan başlık KALIR, kullanıcı verisi `progress/mylist/continue_hidden` silinmez), config dosyaları kalkar, `settings.forget_site`, çalışan iş varsa 409 `busy`; tombstone `DATA_DIR/deleted_sites.json`; `deploy.sh` `DELETED`/`REMOVE` sınıfı (`docs/arch/ops-deploy.md`). Otomatik tarama yazma `PUT /api/ops/settings` `sites.<site>`, tarama `POST /api/ops/sites/{site}/scan`.

## Site devir notu

- **Site devir notu (per-site handoff)** `scraper/site_handoff.py`, `DATA_DIR/site_handoffs/<site>.md` (≤6 KB, atomik, kilit; deploy'da `data/` korunur): heal ajanı TÜM geçmişi değil bu notu okur (`GET /site_config/{id}` -> `handoff`, araç `load_site_config`).
