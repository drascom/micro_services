## Kullanıcı kararı: admin eylemleri bütçe dışı
- Karar: "bütçeyi 400 yaptım ama benim komutlarım bütçeye sayılmamalı". Önceki "okuma her zaman `background=True`, admin koşusu bütçe dolunca LLM'siz devam eder" davranışı KALDIRILDI: admin bilerek başlattığı koşuda LLM'i istiyor; sessizce LLM'siz kalmak hem kararı çiğniyor hem de 400'lük günlük sayacı admin işleriyle tüketip sistemin onarımlarını aç bırakıyordu.
- `engine.enqueue(..., trigger="admin"|"system")` (varsayılan admin; `background=True` = system; onarımda `repair.admin`). İş yükünde `trigger` + `background` (checkpoint ile yeniden başlatmaya dayanıklı). Admin koşusunun tüm çağrıları (ilk okuma, turlar, biçim düzeltmesi, inceleme adımları, A6 tarifi) bütçeye takılmaz, `llm_calls.background=0` yazılır, `budget.spent_today` saymaz.
- Zincir: `queue_followers(site, trigger_of(p))` -> admin A2'yi başlatınca A3..A7 de admin; zincir bir sistem koşusu (crawl/onarım/gap kataloğu/otomatik) başlayana dek sürer, o noktadan sonrası system. İnceleme onayı (admin) zinciri admin yapar. A6 -> A5 geri devri mevcut tetikleyiciyi taşır.
- Sorunlar: `run.enqueue(admin=True)` (yeniden dene, admin bildirimi, geri alma, motor boşluğu "shipped"), yük checkpoint'lerinde korunur -> `repair.start(admin=True)`; başarısız tur sonrası otomatik geri deneme system. İpucu zaten admin.
- Kart: "LLM çağrısı: N (senin başlattığın, bütçe dışı)" / "(sistem, bütçeden)" (son koşu, `status.llm_line`); Ayarlar "son 7 gün" tablosunda Admin (bütçe dışı) / Sistem (bütçeden) ayrı sütun.
- Testler `tests/test_admin_budget.py` (3): bütçe 0 + admin -> LLM çağrılır, sayaç 0, satır background=0, kart satırı; bütçe 0 + sistem onarımı -> çağrı yok; admin zinciri A3 yükünde `trigger=admin` (DB'den okunur). `test_t23` iki test yeni karara göre güncellendi.
